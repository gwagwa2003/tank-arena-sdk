# 觀測：模型每一步看到的 91 個數字

`tank_arena.observation(state)` 產生的就是伺服器餵給模型的觀測（逐位相同）。
所有角度都是**相對於自己車身朝向**的角度，用 sin、cos 兩個數表示（右轉方向為正）。

## 0–31：地形射線（32 個）

從車身正前方開始，每隔 11.25°（π/16）往右轉一條射線，量到最近的牆或場邊的距離，除以 320（帶雷達時除以 430），最大 1。

## 32–55：看得到的敵人（最多 4 個，每個 6 個數，由近到遠）

| 偏移 | 內容 |
|---|---|
| +0 | 1（這格有敵人）；沒有就整組都是 0 |
| +1 | 距離 ÷ 視線距離（340，帶雷達 450） |
| +2, +3 | 敵人方向的 sin、cos |
| +4 | 敵人速度在我前方方向的分量 ÷ 6 |
| +5 | 敵人速度在我右方方向的分量 ÷ 6 |

1 對 1 只會用到第一組（32–37）。

## 56–75：附近的敵方子彈（250 像素內最多 4 顆，每顆 5 個數，由近到遠）

| 偏移 | 內容 |
|---|---|
| +0 | 1（這格有子彈） |
| +1 | 距離 ÷ 250 |
| +2, +3 | 子彈方向的 sin、cos |
| +4 | 子彈朝我接近的速度 ÷ 14（正值＝在接近） |

## 76–90：自己、安全區、時間、技能

| 索引 | 內容 |
|---|---|
| 76 | 剩餘血量比例 0–1 |
| 77 | 裝填剩餘步數 ÷ 機體裝填步數（最大 1；0＝可以開火） |
| 78 | 這一步實際移動量在前方方向的分量 ÷（機體速度 × 2） |
| 79 | 這一步實際移動量在右方方向的分量 ÷（機體速度 × 2） |
| 80, 81 | 砲塔相對車身的角度 sin、cos |
| 82, 83 | 安全區圓心方向的 sin、cos |
| 84 | 到安全區圓心的距離 ÷ 800 |
| 85 | （安全區半徑 − 到圓心距離）÷ 620，夾在 −1～1（負的＝在圈外） |
| 86 | 毒圈縮小進度：（620 − 半徑）÷ 530，0～1 |
| 87 | 目前步數 ÷ 1,200 |
| 88 | 活著的敵人數 ÷ 4 |
| 89 | 技能冷卻剩餘 ÷ 模組冷卻步數（被動模組是 0） |
| 90 | 技能作用中＝1 |

## 疊幀與正規化

模型實際收到的輸入不是原始的 91 個數，伺服器會先處理：

1. 每一幀用 `config.json` 裡的 `mean`、`std` 正規化：`(obs − mean) / std`。
2. 非循環模型（`recurrent: false`）：把最近 `stack` 幀接起來，**最新的在最前面**，開局時不足的幀用最舊的那幀補。輸入大小 91 × stack。
3. LSTM 模型（`recurrent: true`）：一次只給一幀，靠 `h`、`c` 記住過去。

`tank_arena.agent.FrameStack` 做的就是第 1、2 步，收集訓練資料時用它，訓練和比賽看到的輸入才會一致。
